# 산출 내역·증빙 제출·취합 설계서

> **요약**: 교육생이 여비를 계산한 뒤 **산출 내역과 증빙 파일(하이패스·숙박비·교통비 영수증 등)을 제출**하고, 운영자가 한 화면에서 **취합·검증·내려받기·삭제**하는 기능의 설계예요. (구현 전 설계 — 2026-11-12)
>
> **확정한 결정** (사용자 답변): 저장소 = Vercel Blob + Vercel KV / 운영자 접근 = 운영자 비밀번호 하나 / 보관 = 운영자가 직접 삭제 / 교육생 구분 = 이름 + 사번 입력

---

## 1. 왜 필요한가
- 지금은 교육생이 계산 결과를 운영자에게 보낼 방법이 없고, 증빙 사진은 브라우저 미리보기만 해요(서버 저장 없음).
- 운영자는 교육생마다 **산출 내역(입력값 포함)** 과 **증빙(하이패스·숙박·교통비 영수증)** 을 모아서 확인해야 해요.
- 이 설계는 PRD의 비범위 두 개를 **의도적으로 바꿔요**: "교육생 데이터를 서버에 저장하지 않는다", "로그인 없음". → 구현 시 PRD·PLAN을 함께 고쳐요(§10).

## 2. 범위
**만든다**
- 교육생: 결과 화면 아래 "제출하기" (이름·사번·개인정보 동의 → 증빙 파일 올리기 → 제출)
- 운영자: 비밀번호 로그인, 제출 목록·상세, 증빙 보기·내려받기, 산출 내역 CSV 내려받기, 선택 제출 일괄 재산출·비교, 삭제
- `/operator`(일괄 산출)도 같은 비밀번호로 보호

**만들지 않는다**
- 교육생 개별 로그인·회원가입, 수정·재제출 편집 화면(다시 제출하면 새 건), 증빙 자동 인식(OCR), 이메일·알림 발송, 자동 삭제(보관 = 운영자 직접 삭제)

## 3. 사용 흐름

**교육생**
```
결과 확인 → [제출하기] → ① 이름·사번 입력 + 개인정보 수집·이용 동의 체크
→ ② 증빙 올리기: 종류 선택(하이패스 / 숙박비 / 교통비 / 기타) + 파일(사진·PDF) 여러 개
→ ③ 제출 → 접수 번호 표시 ("접수 번호를 운영자에게 알려 주세요")
```
- 제출 내용: 입력값(교육 장소·기간, 구간, 교통수단, 실비, 숙박·식비 입력), 계산 결과(항목별 금액·근거·경고), 조회 근거(철도 요금표, 거리, 휘발유 가격), 증빙 파일, 이름·사번.
- 서버가 **결과 서명(HMAC)** 을 확인해 조작된 금액은 받지 않아요(기존 `/api/calculate`의 서명 재사용).

**운영자**
```
/operator/login (비밀번호) → 제출 목록 (필터: 교육 장소·기간, 이름·사번 검색, 경고 있음)
→ 제출 상세 (산출 내역 · 조회 근거 · 증빙 미리보기/내려받기)
→ 선택해서 [CSV 내려받기] [증빙 전체 내려받기] [일괄 재산출·비교] [삭제]
```

## 4. 화면
| 화면 | 주소 | 내용 |
|---|---|---|
| 제출 패널 | `/` 결과 아래 | 이름·사번, 동의 체크, 증빙 종류별 올리기(드래그·선택), 올린 파일 목록(삭제 가능), 제출 버튼, 접수 번호 안내 |
| 운영자 로그인 | `/operator/login` | 비밀번호 한 칸 |
| 제출 목록 | `/operator/submissions` | 표: 접수 번호·제출 시각·이름·사번·교육 장소·기간·합계·경고·증빙 수. 필터·검색, 체크박스 선택, 제출 후 N일 표시 |
| 제출 상세 | `/operator/submissions/[id]` | 입력값, 항목별 결과와 근거, 조회 근거(요금표·경로·가격), 증빙 파일 갤러리(이미지 미리보기·PDF 열기·내려받기) |
| 일괄 산출 | `/operator` | 기존 화면(비밀번호 보호). 제출 선택 → 재산출 결과를 제출값과 비교해 차이 표시 |

## 5. 저장 구조

### 5.1 저장소 역할
| 저장소 | 넣는 것 | 이유 |
|---|---|---|
| **Vercel Blob** | 증빙 파일(이미지·PDF) | 큰 파일 저장용 |
| **Vercel KV**(Redis 계열) | 제출 기록(JSON), 목록 색인, 로그인·요청 횟수 제한 카운터 | 작은 구조 데이터, 빠른 조회 |

### 5.2 제출 기록 (KV `sub:{id}` — JSON)
```ts
interface Submission {
  id: string;                 // 접수 번호: 짧은 무작위(예 "K7M2-9QXA"), 추측 어려움
  createdAt: string;          // ISO
  submitter: { name: string; employeeNo: string };   // 개인정보
  consent: { agreedAt: string; version: string };    // 동의 기록
  input: CalculationInput;    // 교육 장소·기간·구간·실비 입력 (customCourse 포함)
  result: CalculationResult;  // 항목별 금액·근거·경고
  meta: { fetchedAt: string; notes: string[]; evidence?: LookupEvidence };  // 조회 근거
  files: SubmissionFile[];
  status: "draft" | "submitted";   // draft는 파일 올리는 동안만
}
interface SubmissionFile {
  id: string; kind: "highpass" | "lodging" | "transport" | "other";
  name: string;               // 원본 이름(표시용, 경로에는 쓰지 않음)
  size: number; contentType: string;
  blobPath: string;           // submissions/{id}/{fileId}.{ext}  (원본 이름 사용 안 함)
}
```
- 목록 색인: `subs:index` (정렬 집합, 점수 = 제출 시각) + 건별 요약 `sub:{id}:sum`(목록 표에 필요한 최소 필드).
- 제출 건수가 많아도(교육 1회 110명 × 여러 회차) 목록은 요약만 읽어 빠르게 보여줘요.

### 5.3 저장소 추상화
`lib/submissions/store.ts`에 `SubmissionStore` 인터페이스(create / addFile / finalize / list / get / delete)를 두고 **Vercel 구현**과 **메모리 구현(테스트·로컬)** 을 둬요. 키가 없는 로컬에서도 개발·테스트가 돼요.

## 6. 서버 API
| 메서드 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/submissions` | 제출 초안 생성: 이름·사번·동의·입력·결과·서명 검증 → 접수 번호와 1회용 업로드 키 반환 | 누구나(요청 제한) |
| POST | `/api/submissions/upload` | Blob 직접 업로드 승인(토큰 발급): 접수 번호·업로드 키 확인, 파일 형식·크기·개수 제한 | 업로드 키 |
| POST | `/api/submissions/[id]/finalize` | 올라온 파일 확인(실제 존재·크기) 후 `submitted`로 확정 | 업로드 키 |
| POST | `/api/operator/login` · `/logout` | 비밀번호 확인 → 세션 쿠키 | 비밀번호 |
| GET | `/api/operator/submissions` | 목록(필터·검색·페이지) | 운영자 |
| GET | `/api/operator/submissions/[id]` | 상세 | 운영자 |
| GET | `/api/operator/files/[submissionId]/[fileId]` | 증빙 파일 내려주기(서버가 Blob에서 읽어 전달) | 운영자 |
| GET | `/api/operator/export?ids=…` | 산출 내역 CSV | 운영자 |
| POST | `/api/operator/recalculate` | 선택 제출을 다시 산출해 제출값과 비교 | 운영자 |
| DELETE | `/api/operator/submissions` | 선택 제출과 그 증빙 파일 삭제 | 운영자 |

- 파일은 **브라우저에서 Blob으로 바로 올려요**(서버리스 요청 크기 한도 약 4.5MB를 피하려고). 서버는 업로드 승인과 확정만 해요.
- 증빙 파일은 **운영자 API를 거쳐서만** 내려가요(Blob 주소를 화면에 노출하지 않음).

## 7. 보안·개인정보 설계
| 위험 | 대응 |
|---|---|
| 이름·사번·영수증(카드번호·성명 노출 가능)이 서버에 저장됨 | 제출 전 **수집·이용 동의 체크**(항목: 이름·사번·산출 내역·증빙 / 목적: 여비 정산 확인 / 보관: 운영자가 삭제할 때까지). "카드번호·주민등록번호는 가려서 올려 주세요" 안내. AI(OpenAI)에는 제출 내용을 보내지 않음 |
| 증빙 파일 URL이 새면 누구나 열람 | 파일 경로를 무작위(원본 이름 미사용)로 만들고, 운영자 API로만 노출. Vercel Blob의 **비공개 저장 지원 여부를 구현 전에 확인**하고 가능하면 비공개로 저장 |
| 운영자 비밀번호 추측·무차별 대입 | 환경 변수 `OPERATOR_PASSWORD`와 상수 시간 비교, 로그인 **10분 5회 제한**(KV 카운터), 성공 시 `HttpOnly·Secure·SameSite=Strict` 세션 쿠키(8시간, 서명) |
| 운영자 화면이 아무에게나 열림(현재 `/operator`) | `/operator` 전체와 `/api/operator/*`를 프록시(Next.js 16의 요청 가로채기 파일)에서 세션 검사 |
| 악성 파일 업로드 | 허용 형식(JPEG·PNG·WebP·HEIC·PDF)만, 파일당 10MB, 제출당 10개·합계 30MB(업로드 승인 때와 확정 때 두 번 검사). 내려줄 때 `Content-Disposition`·`nosniff` 지정, 실행되는 형식 금지 |
| 제출 폭주·남용(저장 비용) | IP·하루 제출 상한(KV, 기존 메모리 방식 대체), 접수 번호·업로드 키는 1회용·30분 유효, 확정 안 된 초안과 파일은 정리 대상으로 표시 |
| 조작된 금액 제출 | 결과 서명(HMAC) 검증. 운영자는 "일괄 재산출·비교"로 다시 확인 |
| 파일명·이름에 스크립트 삽입 | 화면은 React가 글자로만 표시, 파일명은 표시용으로만 쓰고 정제 |
| 키 노출 | 새 환경 변수(`BLOB_READ_WRITE_TOKEN`, KV 주소·토큰, `OPERATOR_PASSWORD`, `OPERATOR_SESSION_SECRET`)는 서버 전용, `NEXT_PUBLIC_` 금지, Vercel에만 등록 |

**보관(결정: 운영자가 직접 삭제)** — 자동 삭제가 없으므로 잊혀 쌓일 위험이 있어요. 완화: 목록에 "제출 후 N일" 표시, 30일 넘은 건 상단 경고 배너("30일이 지난 제출 N건 — 정산이 끝났다면 삭제해 주세요"), 선택 삭제·교육 장소/기간별 일괄 삭제 버튼, 삭제하면 Blob 파일까지 함께 지움.

## 8. 운영자 취합 산출물
- **산출 내역 CSV**: 접수 번호, 제출 시각, 이름, 사번, 교육 장소, 시작일, 종료일, 가는 편/오는 편(출발지·교통수단·실비·하이패스), 숙박 박수·박별 숙박비, 식비 청구 일수, 항목별 인정 금액(교통비 2·숙박비·일비·식비), 합계, 경고, 증빙 수. (UTF-8 BOM, 엑셀에서 열림)
- **증빙 내려받기**: 건별 파일 내려받기 + 선택 건 묶음 ZIP(브라우저에서 묶음 — 서버리스 시간·크기 한도를 피함).
- **일괄 재산출·비교**: 선택 제출의 입력값으로 `/api/calculate-batch`와 같은 엔진을 돌려 제출값과 다른 항목을 표시(외부 요금이 바뀐 경우 등).

## 9. 구현 순서 (모듈)
1. **저장소 틀**: `SubmissionStore` 인터페이스 + 메모리 구현 + 테스트, Vercel Blob/KV 구현
2. **운영자 보호**: 비밀번호 로그인·세션·프록시, `/operator` 보호, KV 기반 요청 제한 교체
3. **교육생 제출**: 제출 패널(이름·사번·동의·증빙 종류별 업로드), 제출 API 3개, 접수 번호
4. **운영자 취합 화면**: 목록·상세·파일 보기, 삭제, 30일 경고
5. **내려받기·비교**: CSV, ZIP, 일괄 재산출·비교
6. **검증**: 테스트(저장소·권한·파일 검사·서명), 브라우저 확인, 실서비스 업로드 점검, 보안 점검 재실행, 문서 갱신

## 10. 문서·배포에 미치는 영향
- **PRD**: 비범위에서 "교육생 데이터 서버 저장 DB 없음"과 "로그인 없음"을 수정(제출 기능과 운영자 비밀번호 보호 추가), 개인정보 표에 이름·사번·증빙 파일 저장 추가, 사용자 흐름에 제출·취합 추가.
- **PLAN**: 작업 목록(제출·취합 추가), 요구사항(FR), 성공 기준(제출 후 운영자가 확인 가능, 파일 형식·크기 제한, 운영자 접근 보호) 추가.
- **README**: 새 환경 변수, 운영자 비밀번호 안내. **DESIGN**: §12에 반영.
- **Vercel**: Blob·KV(스토어) 생성 후 프로젝트에 연결, 환경 변수 5개 추가 등록. 로컬에서는 메모리 구현으로 개발.

## 11. 구현 전에 확인할 것 (열린 질문)
1. **Vercel Blob 비공개 저장**을 지금 계정에서 쓸 수 있는지(가능하면 비공개, 아니면 무작위 경로 + 운영자 API 전달).
2. **Vercel KV**는 Vercel 스토어 메뉴에서 Redis 제공 업체(Upstash 등)로 연결되는 방식일 수 있어요. 계정에서 어떤 방식으로 만들어지는지 확인.
3. **개인정보 동의 문구**: 기관 규정에 맞는 정식 문구가 있으면 그대로 쓰기(없으면 기본 문구 사용).
4. **사번 형식**(자리 수·문자)이 있으면 입력 검사에 반영.
5. **용량·비용**: 교육 1회 110명 × 증빙 5개 × 2MB ≈ 1GB. 무료 한도를 넘으면 유료일 수 있어요. 삭제 습관이 중요해요.
6. **같은 사람이 여러 번 제출**하면 별건으로 쌓아요(목록에서 최신 건 표시). 덮어쓰기가 필요하면 알려 주세요.
7. 운영자 비밀번호 **교체·분실** 절차(Vercel 환경 변수 수정 후 재배포).

## 12. 완료 기준 (구현 후 확인)
- 교육생이 이름·사번·동의 후 증빙 3종 이상을 올려 제출하면 접수 번호가 나온다.
- 운영자는 비밀번호 없이는 목록·상세·파일·`/operator`에 들어갈 수 없다(주소를 직접 쳐도 막힌다).
- 허용하지 않는 형식·크기·개수는 거절되고, 조작한 금액은 서명 검증으로 거절된다.
- 운영자가 목록에서 건을 열어 산출 내역과 증빙을 보고, CSV·증빙을 내려받고, 삭제하면 Blob 파일까지 지워진다.
- 비밀번호·토큰·키 값이 브라우저 번들·저장소·화면에 없다.
